US-003 DONE (_retry.py shared httpx retry helper):
- Implemented: /Users/jinsungpark/short03/src/md2short/_retry.py
  `post_with_retry(client: httpx.Client, url: str, retries: int = 3,
  backoff: tuple[float, ...] = (0.5, 1.0, 2.0), sleep: Optional[Callable] = None,
  **httpx_kwargs) -> httpx.Response`.
  - Retries on: HTTP 429, any 5xx, httpx.TimeoutException, httpx.TransportError
    (covers ConnectTimeout/ReadTimeout/ConnectError etc).
  - Does NOT retry other 4xx (e.g. 404) -- `response.raise_for_status()` raises
    immediately for those, propagating out un-retried.
  - After exhausting retries, the last exception/HTTPStatusError propagates
    (never swallowed).
  - Sleep is resolved as `(sleep or time.sleep)(delay)` inside the function
    body (not bound as a default-parameter value), so `time.sleep` is looked
    up fresh via module attribute access on every call -- this makes it
    patchable with `unittest.mock.patch("md2short._retry.time.sleep")`
    (a default-arg binding like `sleep: Callable = time.sleep` would NOT be
    patchable this way, since the reference would be captured once at import
    time). Callers may also pass an explicit `sleep` callable directly.
- Retry-count interpretation chosen (architecture.md's "최대 3회 재시도" +
  "0.5/1.0/2.0s backoff" is genuinely ambiguous -- documented in the module
  docstring too): `retries=3` means 3 retries AFTER the initial attempt, i.e.
  up to 4 total attempts, with all three backoff values (0.5s, 1.0s, 2.0s)
  used as the sleep between each of the 4 consecutive attempts. Rejected the
  alternative ("3회" = 3 attempts total, 2 retries) because that would leave
  the 2.0s backoff value permanently unused dead code, which doesn't fit a
  quality-rules table that lists all three durations as meaningful values.
- Tests: /Users/jinsungpark/short03/tests/test_retry.py, using
  `httpx.MockTransport` exclusively (no real network calls) and
  `unittest.mock.patch("md2short._retry.time.sleep")` to assert exact sleep
  call counts/durations without actually sleeping. 7 tests:
  test_immediate_success_no_retry, test_429_twice_then_success,
  test_500_twice_then_success, test_exhausts_all_retries_propagates
  (asserts 4 total handler calls, sleeps [0.5, 1.0, 2.0], and that
  httpx.HTTPStatusError propagates out of post_with_retry),
  test_404_does_not_retry (asserts 1 handler call, 0 sleep calls, error
  propagates immediately), plus two extra coverage tests
  test_timeout_then_success / test_transport_error_then_success for the
  timeout/transport-error retry paths named in the acceptance criteria.

US-007 DONE (numeric_display.py — 숫자/약어 표시 보정):
- Files:
  - /Users/jinsungpark/short03/src/md2short/numeric_display.py (implemented, was empty placeholder)
  - /Users/jinsungpark/short03/tests/test_numeric_display.py (new)
- Design:
  - `_ACRONYM_TOKEN_RE`: compiled regex with three alternatives matched via
    `.fullmatch()` against a single word's text — (1) letters/"&" immediately
    followed by digits (e.g. "S&P500", "AMD10"), (2) letters joined by "&"
    with no digits (e.g. "S&P"), (3) a bare 2+ letter acronym/ticker (e.g.
    "AMD", "AI"). Used only to recognize tokens Scribe already wrote
    correctly, so the fuzzy matcher below never touches/mangles them.
  - `_ACRONYM_KO_VARIANTS` dict (canonical display form chosen: "S&P500" for
    the combined ticker+number case, bare "S&P" for the letters-only case —
    picked to match the two concrete examples in architecture.md and PRD
    AC, kept internally consistent):
      "에센피" -> "S&P500"   (contracted/slurred "에스앤피")
      "에스앤피" -> "S&P"    (letter-by-letter S, "&"("and"), P)
      "에이엠디" -> "AMD"    (letter-by-letter A, M, D)
      "에이아이" -> "AI"     (letter-by-letter A, I)
    Deliberately excludes 코스피/나스닥/다우/니케이/항셍 etc. — these are real
    Korean words for real indices, not phonetic transliterations of an
    English acronym, and must pass through untouched.
  - `ACRONYM_MATCH_THRESHOLD = 0.86` and `ACRONYM_MAX_SCAN_WORDS = 96` are
    wired into `_best_variant_match()`: exact dict match first, else the
    highest `difflib.SequenceMatcher(None, text, variant).ratio()` across
    all variants, accepted only if >= ACRONYM_MATCH_THRESHOLD. This fuzzy
    check is only attempted for word indices < ACRONYM_MAX_SCAN_WORDS in
    `apply_numeric_display_overrides()`, bounding worst-case scan cost on
    long transcripts (verified by a dedicated test: a variant placed at
    index == ACRONYM_MAX_SCAN_WORDS is correctly left unmatched).
  - `apply_numeric_display_overrides(words: list[dict]) -> list[dict]`
    operates on plain dicts (text/start/end keys) rather than importing
    `md2short.schema.CaptionWord`, to avoid a hard import-order dependency
    on the parallel US-002 story. Returns a NEW list; every entry is a
    shallow copy, start/end (and any other keys) are always carried
    through unchanged, and only `text` is ever rewritten. Critical
    invariant (AGENTS.md section 3.2 — words.json is the single source of
    truth for timing) verified by `test_timing_identical_before_and_after_for_every_word`,
    which asserts the full list of (start, end) tuples is identical before
    and after, including that the input list itself is not mutated in place.
  - Multi-word token reassembly (Scribe splitting "S&P500" across separate
    "S&P" + "500" word entries) is explicitly out of scope — documented in
    the module docstring. The narrower, reliably scoped behavior: if a
    single word's text already fully matches `_ACRONYM_TOKEN_RE`, it is
    left alone and skipped before the fuzzy matcher runs.

  mutates its input, builds and returns a new string via a chain of re.sub
  calls applied in this exact order (all documented in the module
  docstring too):
    1. Percent-sign spacing: `(\d)\s*%` -> "<digit> %" (e.g. "50%" ->
       "50 %"; idempotent on already-spaced input).
    2. Acronym+number spacing: `([A-Z]+(?:&[A-Z]+)*)(\d)` -> "<acronym>
       <digit>..." (e.g. "S&P500" -> "S&P 500", "AMD10" -> "AMD 10"; only
       the boundary digit gets a space inserted before it, the rest of the
       digit run is untouched by the regex but ends up correctly
       reassembled since re.sub only consumes the matched span; already-
       spaced input like "S&P 500" does not match and is left alone).
    3. Ellipsis normalization: `\.{3,}` -> "…" (single Unicode ellipsis
       char), so a run of 3+ literal periods reads as one soft pause
       instead of TTS stuttering through each period.
    4. Repeated "!"/"?" collapsing: `[!?]{2,}` -> first char of the
       matched run (e.g. "!!!" -> "!", "?!" -> "?"), to avoid choppy
       multi-beat pauses.
    5. List-bullet softening: `^[ \t]*[-·•※*][ \t]+` (MULTILINE) stripped
       at line start, so "- 항목" -> "항목" (bullet markers otherwise read
       as an odd pause beat).
  These are explicitly judgment-call light-touch transformations (PRD gives
  no exact algorithm) — chosen to be narrow, regex-scoped, and easy to
  reason about/extend later rather than a general NLP-based pronunciation
  engine. Display/caption text elsewhere in the pipeline is completely
  unaffected (this module is never called on it; it's TTS-input-only).
  Purity verified by an explicit design-contract test asserting the
  caller's original string variable is unchanged (and `is` the same
  object) after calling prepare_tts_text — trivially true for Python
  strings but asserted explicitly per the story's design-contract
  requirement.

    * `_FOREIGN_SCRIPT_RE` covers only NON-Latin foreign scripts (kana 3040-30FF/31F0-31FF,

- data_extract.plan_number_cards(script_text, audio_duration_ms, max_cards=6,
  cooldown_ms=2500, duration_ms=1800) -> list[dict]
  Constants: DEFAULT_MAX_CARDS=6, DEFAULT_COOLDOWN_MS=2500, DEFAULT_DURATION_MS=1800
  (architecture.md section 5.9; 1800 also equals NumberCard.tsx's DEFAULT_DURATION_MS).
  One NUMERIC_MENTION_RE pass, alternatives in priority order:
    index    (코스피|코스닥|S&P 500|나스닥|니케이|항셍|다우) + <=10 non-digit chars + number
    currency number + 조|억|만 + 원|달러
    percent  number + % | 퍼센트 | 프로(?![가-힣])
    point    number + 포인트 | p(?![A-Za-z가-힣])
  The index branch declines a number followed by a %/포인트/조억만 unit, so
  "나스닥은 0.94% 상승했습니다" yields a percent card (0.94%), not an index value
  of 0.94. startMs = round(match.start()/len(script_text) * audio_duration_ms),
  clamped to [0, audio_duration_ms]. Cooldown compares against the last *kept*
  card (so a skipped match does not reset the clock). max_cards keeps the FIRST
  N in document order -- documented choice: the script is written narrative-first
  (headline figure first) and document order is trivially deterministic, unlike
  ranking by magnitude where "18%" vs "18조 원" needs an arbitrary tie-break.
  Card dict matches remotion/src/types.ts NumberCard: {"text", "startMs",
  "durationMs", "label"} -- label carries the index name for index matches
  (e.g. "S&P 500" with text "7,230"), None otherwise.

BUG 2a — duration field name. The real field is `audio_duration_secs`, NOT the

correct field makes video and audio agree to 3 ms. The QC tolerance was never
the problem and was NOT touched.

BUG 2b — `type: "spacing"` pseudo-words. Every entry in `words` carries a `type`
discriminator. Only `type:"word"` entries are real tokens; `type:"spacing"`
entries are the WHITESPACE BETWEEN words (their `text` is literally `" "`), and

(`pipeline._opening_duration_ms`, which indexes words by token count) and
emoticon cue placement all index into this list positionally, every one of those
calculations was off by ~2x. Fixed by filtering to word entries.

### BUG A — 5-second default HTTP timeout in voice.py and transcript.py
First real run died with `Error: run_job failed: The read operation timed out`
at the voice stage. Root cause: both modules created `httpx.Client()` with NO
`timeout=`, and httpx's default timeout is 5 SECONDS. Synthesizing a ~1000-char
Korean narration and transcribing a 72-second mp3 both take far longer, so every
real run was guaranteed to fail — and because `_retry.post_with_retry` retries
timeouts, it burned all 4 attempts, each of which still costs credits
server-side. This was invisible to the unit tests because they inject a
MockTransport that answers instantly.
Notably `script_engine.py` (120 s) and `photo_engine.py` already set explicit
timeouts, which confirms the omission was an oversight rather than a convention.

### BUG B — relative paths passed to a subprocess with a different cwd
Second real run died with:
    `npx remotion render` failed with exit code 1
    You passed --props but it was neither valid JSON nor a file path to a valid
    JSON file. Provided value: remotion/public/jobs/<id>/props.json
`render.render_remotion` runs the renderer with `cwd=remotion_dir`, but passed
both `--props=<staged_props_path>` and the output path as PROJECT-ROOT-relative
paths. From inside `remotion/` those resolve to
`remotion/remotion/public/...`, so Remotion could not find props.json (and then
tried to parse the path string itself as JSON, hence the confusing message). The
output path was wrong the same way and would have written final.mp4 to
`remotion/jobs/<id>/edit/final.mp4`. The props.json file itself was always valid
JSON — the path was the problem. Fixed by resolving both to absolute paths.

B1 (US-012 reopened) — OpenAI text cost was ALWAYS $0.00 in production
--------------------------------------------------------------------------------
ROOT CAUSE (two halves, both real):
  1. src/md2short/script_engine.py threw away the `usage` block that the live
     OpenAI Responses API returns. `_plan()` emitted only
     {engine, fallback_reason, model} — no usage was ever recorded anywhere.
  2. src/md2short/pipeline.py called `qc.run_qc(...)` with `script_char_count=`
     and `tts_char_count=` only. `openai_input_chars`/`openai_output_chars`
     defaulted to 0, so `qc.estimate_cost()`'s openai line was structurally
     incapable of being non-zero even on a paid `plan.engine == "openai"` run.

FILES CHANGED:
  src/md2short/script_engine.py
    - new `_CHARS_PER_TOKEN_APPROX = 4` constant (mirrors qc._CHARS_PER_TOKEN_APPROX,
      architecture.md "char/4 token 근사"). plan.openai_*_chars is reported in
      CHARACTERS so qc.estimate_cost() remains the sole owner of the token
      approximation.
    - new `_request_text_chars(payload)`: sums every input[].content[].text length.
    - new `_usage_chars(body, payload, output_text) -> (input_chars, output_chars)`:
      prefers the response's own `usage` block (`input_tokens`/`output_tokens`,
      converted with tokens*4 — this is the ONLY source that sees reasoning

    - `_plan()` now always carries `openai_input_chars` / `openai_output_chars`,

      engines, which bill no OpenAI text usage.
